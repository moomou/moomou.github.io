Flow Matching and Back to the Basics #

When I first dove into Flow Matching, the concept felt like a natural evolution, but recent literature has significantly clarified the “where” and “how” of the learning process.

Specifically, Paper X [1] suggests that manifold learning is most effective when it is concentrated on the data plane rather than the noise plane.

There is something intuitive about this—focusing the model’s capacity on the actual structure of the data rather than the chaos of the Gaussian prior.

In practice, the authors obtained their best results by configuring the model to predict the original data ($x_0$) while training on the velocity ($v$) loss.The most striking takeaway for me, however, wasn’t just the performance, but the sheer simplicity of the logic. I don’t know about you, but in this field, the simpler the explanation, the more I start to trust the method. When a framework is this elegant, it makes me feel that the researchers didn’t just find a workaround—they actually uncovered a fundamental truth. It’s that “aha!” moment where the math aligns so perfectly with the intuition that you wonder why we ever did it any other way.

Image to Patch Tokens #

In order for the transformer to interact with images, which is represented as tensor of shape (C, H, W), we need to encode images into a sequence of “tokens”. Following standard literature practice, we will patchify the image; that is, we will chop the image into a sequence of smaller square images of size p and obtain a tensor of size (T, C’), where T = H * W // (p * p) and C' = p * p, assuming a stride of p, which results in no overlapping patches.

The patchify function is conveniently available inside torch.nn.functional module as

  F.unfold(
    img_tensor, 
    kernel_size=patch_size, 
    stride=patch_size)

The inverse function is

  folded_sum = F.fold(
    unfolded, 
    output_size=(H, W), 
    kernel_size=patch_size, 
    stride=stride)

Here is a screenshot showing visually what patchify looks like when stride is set to patch_size.

It can be beneficial to set stride lower than patch_size, say 50% or 25% to give our model more information. If our patches overlap (ie stride is less than patch), then when folding (turning patches back into image), it’s important to make sure to account for the overlap with a normalization mask.

    # Create a normalization mask (fold a tensor of ones)
    ones = torch.ones_like(unfolded)
    norm_mask = F.fold(
      ones, 
      output_size=(H, W), 
      kernel_size=patch_size, 
      stride=stride)
    folded_norm = folded_sum / norm_mask

In flow matching model, instead of feeding a clean image, we will feed a corrupted image. Let x be a clean image and z(t) be a corrupted image, where t represents time. z(0) is pure noise and z(1) equals x.

z ( t ) = x ⋅ t + ( 1 − t ) ⋅ noise

Following the paper X, we will make our transformer predict x (image space) and use velocity loss (v) as our loss function.

That is, given t and corrupted input z,

x predicted = ViT ( z , t )

Using x predicted, loss function is

v ground truth = x orig − z 1 − t
v predicted = x predicted − z 1 − t
Loss = ∥ v pred − v gt ∥ 2

Euler’s Method #

One of the core mechanisms of the Flow Matching algorithm is the need to iteratively solve an Ordinary Differential Equation (ODE). Specifically, we will leverage our flow matching model to derive a velocity field (position over time), and use that to nudge our image (position) step by step until we get a noise free version.

While many implementations use complex adaptive solvers, in keeping with the spirit from scratch as much as possible, I have chosen to go with implement Euler’s method.

The core idea is this - suppose you have a function X(t) and you know the derivative of X (dxdt) and its value at a specific t. To estimate the value of X at new value t2, we can start from X(t), take a small step in the directions of the dxdt(t), arrive at new value X(t + epsilon). In equation form

x ( t + ε ) ≈ x ( t ) + d x d t ( t ) ⋅ ε

We can repeat this process until we arrive at t2 and get at an estimate for X(t2).

The smaller the epislon, the better the approximateion and the smaller the error.

@torch.no_grad
def euler_method(y0, x0, x1, dfdx):
    x = x0
    x_tensor = torch.tensor(x).to(y0.device)
    
    y = y0
    B = y.shape[0]
    while x < x1:
        dfdx_val = dfdx(y, x_tensor.repeat(B))
        y = y + step_size * dfdx_val
        x += step_size
        x_tensor = torch.tensor(x).to(y0.device)
    return y
